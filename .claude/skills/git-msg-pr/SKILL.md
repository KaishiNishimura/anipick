# PRタイトル・説明文生成

現在のブランチとマージ先ブランチの差分を分析し、PRのタイトルと説明文を提案する。
実際のPR作成は実行しない。

## 手順

1. マージ先ブランチを特定する:
   - `$ARGUMENTS` が指定されていればそれをマージ先とする
   - 未指定なら `develop` をデフォルトとする
   - マージ先ブランチが存在しない場合は `main` にフォールバック

2. 変更状況を確認する:
   - `git log --oneline <base>..HEAD` でコミット一覧を取得
   - `git diff --stat <base>..HEAD` で変更ファイル・規模を把握
   - `git diff <base>..HEAD` で変更内容の詳細を確認（大量の場合は主要ファイルに絞る）
   - 必要に応じてソースファイルを Read で確認

3. 変更内容を分析する:
   - 変更の種類を判定（新機能 / バグ修正 / リファクタリング / ドキュメント等）
   - 影響範囲を特定（どの feature / core モジュールに影響するか）
   - 変更の目的・背景を要約

4. PRタイトルと説明文を生成する:
   - 既存コミット履歴のスタイル（接頭辞・言語・文体）に合わせる

## 出力フォーマット

以下の構成で出力する:

### PRタイトル

- 70文字以内
- Conventional Commits 形式の接頭辞（`feat:`, `fix:`, `refactor:` 等）
- 変更の本質を端的に表現

### PR説明文

```markdown
## Summary
- 変更内容の要約（箇条書き、1〜3項目）

## 主な変更点
### カテゴリ別の変更内容（見出し＋箇条書き）

## 影響範囲
- 変更ファイル数・行数
- 削除したファイル・モジュールがあれば記載

## Test plan
- [ ] テスト項目のチェックリスト
```

## 注意事項

- 絶対にPRを作成しない（`gh pr create` を実行しない）
- `git push` を実行しない
- メッセージの提案のみ行う
